# STRUCTURE.md — where everything lives and where new things go

Three organising rules explain the whole layout:

1. **Stages are directories, and each stage writes a readable artifact to `data/NN_<stage>/`.**
   A stage never reaches past its neighbours. It reads the previous stage's file and writes its own.
   This is what makes every phase auditable and every rerun resumable.
2. **Series-specific knowledge lives in `config/`, never in `src/`.** No character name, faction,
   volume count or EPUB quirk appears in Python. Adding a new series is adding a YAML file.
3. **Code runs from `src/` or `scripts/`; `docs/` holds only text and data.** A `.py` file under
   `docs/` is misplaced.

The per-module map of `src/narrativewiki/` is `CLAUDE.md` §5. It is not repeated here.

## Where do I put new things?

| If you are adding… | It goes in | And you must also |
|---|---|---|
| A new series | `corpus/<id>/*.epub` + `config/series.<id>.yaml` | Inspect the EPUBs before writing quirks |
| A new EPUB quirk | `ingest/epub.py` + a quirk entry in `config/series.*.yaml` | Add a golden test in `tests/` |
| A new entity type | `config/extraction.yaml`, then `entities/classify.py` | Decide its page routing in `site/wikify.py` |
| A new attribute or predicate | `config/extraction.yaml` (+ `extract/schema.py` for attributes) | Document it in `docs/CONTRACTS.md` §3 |
| A new model provider | `llm/providers/<name>.py` + a profile in `config/models.yaml` | Nothing else calls providers directly |
| A new CLI command | `cli.py` | Document it in `USER_GUIDE.md` |
| A new stage report | `audit/reports.py` | Register it in the `audit` command |
| Anything that reads or writes `data/` | A helper in `paths.py` | Never build the path inline |
| A replay / A-B / one-off analysis | `scripts/eval/` or `scripts/probe/` | Write output to `docs/eval/` or `docs/probe/`; add a row to `docs/MEASUREMENTS.md` |
| A measured number or observation | A row in `docs/MEASUREMENTS.md` | Include the command and run id |
| A decision or requirement | A dated entry in `docs/vision/PHASE_<open>.md` | A one-line pointer in `VISION.md` |
| An executable plan | `docs/vision/plans/NNNN-<slug>.md` (next free number) | Keep its Status line current |
| A paper | `docs/papers/pdf/{Paper Title}.pdf` | A row in `docs/papers/PAPERS.md`; arXiv papers also in `fetch_reference_pdfs.py` |
| A literature review for a plan | `docs/papers/reviews/NNNN-<slug>.md` | Link it from plan NNNN |
| The paper (LaTeX) | `docs/paper/` (`sections/`, `tables/`, `appendix/`, `results.tex`) | A number goes in `results.tex` only after its `docs/MEASUREMENTS.md` row; `scripts/papers/paper_status.py` |
| Gold data for `wiki audit eval` | `docs/eval/gold/<series>/*.yaml` | — |

## Naming conventions

- **Top-level and `docs/` prose files:** `UPPERCASE.md` (`CONTRACTS.md`, `MEASUREMENTS.md`).
  Per-phase files: `PHASE_<n>.md`. Plans and reviews: `NNNN-kebab-slug.md`, the number shared.
- **Python:** `snake_case.py`. Script outputs: `<what>_<series-id>[_vNN].json(l)`.
- **Papers:** `{Paper Title}.pdf`, `:` → ` - `; a second edition of the same paper gets
  ` (vN)` or ` (<venue>)` (`docs/papers/PAPERS.md`).
- **Series ids:** kebab-case, identical in `config/series.<id>.yaml`, `corpus/<id>/`,
  `data/<id>/`, `dist/<id>/` and `--series <id>`.
- **Volumes are 1-indexed integers everywhere** (`vol=1`…), never filenames or zero-indexed.

## Conventions

- **Module headers are contracts.** Every module opens with a docstring giving its inputs, outputs,
  invariants and the `CONTRACTS.md` section it implements. Keep them accurate when you change
  behaviour.
- **Stage outputs are JSONL when per-record and JSON when whole-object**, always UTF-8 (no BOM),
  always human-readable.
- **Every fact carries `first_vol` and an evidence reference.** A claim without provenance is a bug.
- **Nothing outside `llm/` calls a model.** If you need a model in a new module, take a client.
