# docs/papers/PAPERS.md — how every PDF in this project relates to it

**Hand-maintained.** Keyed by filename, not arXiv id, so a row lines up with what a reader
sees on GitHub. Companion to `docs/papers/REFERENCES.md` (machine-verified titles/dates/authors,
regenerated by `scripts/papers/fetch_reference_pdfs.py`, id-keyed, do not hand-edit) — this file adds
the two axes that script doesn't track: **Status** (has this paper's technique actually
been implemented, or is it a citation) and where in the repo it lands.

## Naming convention

`{Paper Title}.pdf`, exactly as arXiv gives the title, with `:` replaced by ` - ` and a
version suffix as ` (v1)` / ` (v2)` **only** when two different arXiv versions of the same
paper are both kept (rare — most papers keep exactly one file, unsuffixed). A non-arXiv
edition kept beside the arXiv one takes its venue instead, e.g. ` (EMNLP 2024)`. Established by
commit `497087f` (renamed all 54 files from `{arxiv_id}.pdf`) but never written down until
now; `scripts/papers/fetch_reference_pdfs.py` enforces it (see "Maintaining this file" below).

## Status vocabulary

- **Applied** — this paper's technique is implemented in a named module, right now.
- **Failed** — this paper's technique WAS implemented, then measured worse and removed.
  *(None of the 54 papers below currently carry this status — see the note under §4.1
  in `docs/archive/CAPABILITY_REFERENCE.md`: several internal mechanisms failed and were
  replaced, but each failure is attributed to a design decision this project made, not to
  a cited paper's own method being tried and found wanting. Update this file the day that
  changes.)*
- **Reference** — cited for a design decision, a comparison number, or positioning; its own
  technique is not implemented in this repo's code.

Reading status is a separate axis from Status above (a citation can justify a decision from
its abstract alone) and is noted per-row only when a paper has been read beyond its title —
currently 4 of 54 (`docs/archive/CAPABILITY_REFERENCE.md` §8, R15's still-open half).

## Maintaining this file

1. New PDF lands in `docs/papers/pdf/` (by hand, or via
   `python scripts/papers/fetch_reference_pdfs.py`, which now downloads under the title filename
   directly — see that script's own header).
2. Add its `(arxiv_id, section, why_this_repo_needs_it, status)` tuple to
   `fetch_reference_pdfs.py`'s `PAPERS` list.
3. Add a row here, in the matching section, with the real Status/Where/Note.
4. `python scripts/papers/fetch_reference_pdfs.py --check` verifies every `PAPERS` entry has a file
   on disk and every PDF on disk has a `PAPERS` entry — run it before committing either
   side out of sync.
