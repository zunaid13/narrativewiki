**Summary and strengths.** NarrativeWiki builds an evidence-bearing graph from a series and renders a linked reference at a reader's completed-volume cutoff. Its threat model includes prose, facts, identities and delivered navigation. On five Anne books, it is compared with prefix long-context generation, prefix retrieval, a LightRAG adaptation and additional construction/memory/instruction diagnostics. The pilot finds no confirmed assessed future-fact disclosure from systems whose generator receives eligible material, approximately similar gold-fact recall to the strongest text-reading alternatives, more generated content, worse whole-artifact page support and much weaker paragraph-citation sufficiency. It also documents later-volume effects on early identities that the future-fact metric does not capture.

The task formulation, separation of reading order from story chronology, multi-surface evaluation, construction-dependence examples and candid negative findings remain valuable. The new distinction between true assertions and misleading pair-page placement substantially improves interpretation. The common-page comparison, page-kind breakdown, coverage matrix and finite-probe language all help readers understand what was actually measured. These are meaningful revisions.

**Remaining concern 1: the central labels still need independent validation.** Section 5, pp. 5–6, lines 368–390, and Limitations, p. 9, now state the pilot status clearly. This resolves the disclosure problem in the presentation, but does not establish label accuracy. Gold facts, earliest reveal volumes, factual support, citation support and stated/implied disclosure remain agent decisions. The differing annotator assignment for NarrativeWiki's early precision cells remains a possible confound. Rechecking with the same agents cannot measure the residual error rate.

The package now contains 120 support items and 60 disclosure items from six systems, but no returned reader or adjudication files were present. Complete a blinded double-annotation study after correcting the package issues below. Report category agreement, abstention rates, adjudication and agent-versus-human errors by system, cutoff and page kind. The sample includes previously positive labels, which is useful because the earlier audit reread negatives only.

Add a small independent check of gold facts and first-reveal volumes. The disclosure package supplies the proposed later fact and reveal date as premises; it cannot validate those premises by asking whether a page sentence implies them. In particular, a missed earlier sufficient statement changes which claims are legitimate spoilers. Human factuality validation and gold chronology validation answer different questions.

The prepared sample intentionally oversamples agent-negative support labels. Use label-stratum error rates and sampling weights if estimating corrected population precision. An unweighted support fraction from the 20 items per system would not estimate the original uniformly sampled M3 population.

**Remaining concern 2: the human package requires corrections before use.** These are checks of the released preparation, not claims that human results have already been corrupted.

1. **Citation evidence is truncated.** [make_package.py](../../eval/human/make_package.py) caps each displayed citation list at six paragraphs, while Appendix B, p. 12, defines M8 using every cited paragraph. In the actual package, **31 support items** have raw lists longer than six. A human may call a citation insufficient because the package omitted its supporting paragraph. This is especially concerning because Appendix B identifies reliance on the first six citations as a cause of an earlier audit error. Display the complete eligible citation list, or explicitly define and recompute a different six-paragraph metric.
2. **Missing and undecidable answers become negative decisions.** [score.py](../../eval/human/score.py) retains a row if any answer among the first columns is filled, then applies binary predicates to each scored column. A synthetic diagnostic confirms that both `cannot tell` and a blank support cell with a filled citation answer become support zero. Preserve missing answers per metric, report coverage, and distinguish undecidable from negative judgments. If a conservative all-item score deliberately counts uncertainty as failure, label it separately from agreement among determinate answers.
3. **Pair participation is collected but ignored by the page-support score.** Part A asks whether both characters participate, but `score.py` compares the primary support answer directly with `agent_page`; the pair column is never used. Instructions ask the primary answer to establish the blue statement from the supplied passages, which naturally yields atom support. **Six sampled pair-page items** have positive agent atom support and partial page support. A reader can validly answer “yes” to the factual statement and “no” to joint participation, yet the current scorer treats that as positive page support. Define atom support and page support separately, and combine the pair-participation judgment into the page-context outcome where appropriate.
4. **Retrieved passages cannot certify global absence.** Instructions say readers need not read the books and should judge only shown passages. The package adds a few paragraphs by word overlap. These can establish a positive, but failure to find support in them does not prove absence from the complete eligible prefix. The `no` rule (“nothing shown establishes it”) overlaps with `cannot tell`. Provide access to the eligible source for factuality negatives and chronology checks, or define the limited-context outcome explicitly and keep it separate from M3. Citation sufficiency can remain a closed-evidence judgment because its evidence set is itself the target of that metric.

These changes are necessary to make the proposed validation measure the same outcomes as the paper. Complete them before asking readers to annotate, so returned files do not need reinterpretation after the fact.

**Remaining concern 3: the new sensitivity analysis verifies the classifier, but its positive fixtures are not all validated disclosures of their assigned facts.** Section 6.1, p. 6, and Table 8, p. 15, are useful additions. I reproduced the reported classifier counts: direct **220/220**, named paraphrase **185/220**, own-page pronoun paraphrase **168/220**, other-page pronoun paraphrase **64/220**, named oblique **60/220**, own-page pronoun oblique **32/220**, and other-page pronoun oblique **11/220**. There are 88 underlying later-fact entries, repeated across applicable cutoffs; the 220 trials are fact-by-cutoff units, not independent authored facts.

However, the fixtures in [anne_seeds.yaml](../../eval/m4_seeded/anne_seeds.yaml) were written by an agent, and the premise that each oblique sentence implies its assigned gold fact needs checking:

| Assigned gold fact | Oblique seed | Problem to resolve |
|---|---|---|
| Carl gets a sore throat after getting wet in the Rainbow Valley marsh | Carl is nearly lost to pneumonia after a night's penance in the graveyard | Changes both illness/event description and circumstances. It may reveal another later event, but does not establish this assigned fact. |
| Una is ten years old | Una is a year younger than her sister Faith | Does not establish ten without an eligible premise fixing Faith's age. Supply that premise or change the target. |
| Diana marries Fred Wright | Diana leaves Orchard Slope for a home of her own | Does not identify Fred or necessarily assert marriage. Any intended pragmatic implication must be justified by the reader's eligible context at each tested cutoff. |

These are semantic concerns, not discrepancies in the reported arithmetic. A sentence about a different future event can be a spoiler while still being an invalid positive for recall of this particular gold proposition. Validate each variant against the declared inference criterion and cutoff-specific background knowledge; keep ambiguous fixtures in a separate category. Describe them as agent-authored, rather than leaving “hand-written” open to interpretation as human-authored.

There is also a scope distinction: [m4_seed_test.py](../../../scripts/eval/m4_seed_test.py) calls the sentence classifier directly with an explicit own-page flag. It does not insert text through the real Markdown sentence parser, alias/page identification, candidate extraction and judgment pipeline. Thus the experiment is useful classifier sensitivity evidence. It does not yet establish complete disclosure-audit recall across titles, links, metadata, source pages and rendered prose. Add deterministic examples through the actual candidate-extraction path and a human review of sampled no-candidate regions. Preserve a distinction between “no candidate” and “candidate reviewed as absent.”

The new check of future content in the precision samples is independent of the M4 candidate selector, but uses the existing agent support judgments and notes. It supplies useful complementary evidence; it is not an independent validation of either the annotators or the zero-disclosure conclusion.

**Remaining concern 4: a paired-comparison definition still disagrees with the calculation.** Section 5, p. 6, lines 395–397, says paired differences use entities and cutoffs that both systems have. Section 6.2 also describes the B5–B2 recall difference as over shared cutoffs. The paired branch of [paper_numbers.py](../../../scripts/eval/paper_numbers.py) intersects character keys but averages each system's entire available trajectory. B5 includes cutoff one; B2 starts at cutoff two.

The stored difference is **.0512412644**, CI **[−.0641695152, .1286557770]**. Intersecting actual character/cutoff cells before applying the same bootstrap gives **.0503466450**, CI **[−.0667802454, .1266018261]**. The effect is small in this comparison and changes no qualitative conclusion. Nevertheless, the printed value does not implement the described estimand. Correct the cell intersection and audit other paired metrics, especially sparse citation samples where shared entities may not have observations at identical cutoffs. Preserve the whole-artifact comparisons alongside clearly defined matched comparisons.

Table 1, p. 7, still calls all intervals bootstraps “over characters,” while the setup now uses page entities, including pairs and participant sets. Update the caption and output metadata to describe the actual unit. Explain how shared characters across different pair/scene clusters affect the interpretation of uncertainty; these intervals do not capture model-run variation or label error.

Appendix G, p. 14, lines 1055–1058, also says that approximately 160 sampled assertions per system bound later-volume assertion share at roughly 2%. State the confidence level, zero-event condition, population and sampling assumptions. A binomial rule-of-three calculation is conditional on a suitable independent/random sampling model and reliable disclosure labels; it is not a search-sensitivity-corrected bound on all spoilers. The pooled sample spans cutoff-specific inventories, and some diagnostic systems have positive events. Reconcile this statement with Appendix B's explicit concern about correlated observations. If the design assumptions are not established, report the counts and a clearly conditional calculation.

Algorithm 1's new local copies resolve the previous apparent mutation of the shared graph. There is a smaller specification ambiguity: the empty-interval guard precedes the `VERIFIED` filter, so an initially nonempty set can become empty if rejected intervals are allowed as input. The stated precondition already calls the input verified, which may make the later filter redundant. Clarify the precondition or place the no-page guard after filtering. This is not evidence of a runtime defect by itself.

**What remains empirically limited, and how strongly to require more experiments.** The shared-page structural analysis is a useful improvement. It checks titles, aliases and relation lines, and appropriately declines to attribute every difference between independent runs to the suffix. It does not establish suffix invariance of evidence selection, canonical links or generated prose. The existing Walter example already establishes that construction dependence deserves its own outcome; retain that distinction even if M4 remains zero.

The paper now explicitly says extra content's value to readers was not measured. This adequately limits a pilot claim about amount of output. A stronger utility claim would require a compact reader task, such as answering reference questions at a cutoff, with answer correctness, spoiler exposure and navigation effort. This would be more informative than counting more pages. Such a study would strengthen a systems paper but is not the first correction needed for this pilot.

The single development series, single generator and memorization remain limits to external validity. A frozen held-out run would address immediate cross-work uncertainty; a new runner or freeze record alone does not add evidence to the manuscript. Name replacement or paraphrasing would require fidelity and recognition checks before being called decontamination. I would not require every genre, language and model for publication. A defensible limited empirical claim plus credible independent validation is the relevant standard.

The verifier challenge remains synthetic. Its reported result can support that challenge-set statement; it cannot establish effectiveness on the pipeline's real extraction errors. If architectural error reduction is promoted as a main contribution, evaluate admitted/rejected real candidates and separate literal quotation validity from entailment. The revision's acknowledgment of this distinction is welcome.

The completed-volume granularity and within-volume conflict policy are now explicit. They can be acceptable scope choices for a pilot. Distinguish an interval's earliest extracted supporting evidence from the true earliest sufficient statement, and avoid treating every cross-volume difference as genuine story change rather than an error, rumor or changed belief.

**Limitations, ethics and artifact usefulness.** The limitation and ethics sections now disclose agent annotation, memorization, public-domain scope, completed-volume cutoffs and unfinished human validation candidly. The intended benefit and primary failure mode—helpful references that may still mislead or spoil readers—are understandable. I see no additional reason, from this manuscript, to request a separate ethics review. Report consent, compensation, source familiarity and actual annotation time when human results are added. Prepared instructions or estimated time should not be presented as completed participant information.

The code and released artifacts look useful for inspecting and extending this task. I would tentatively rate dataset usefulness **3/5** and software usefulness **3/5**; label validation and a stable evaluation protocol could raise their value. The archive substantially improves the ability to recompute stored results, while dependency specifications, provider changes and absent raw response caches still limit exact fresh regeneration. Confirm that reviewers receive the archive through the submission interface; an anonymous attachment can satisfy that requirement without a public URL.

**Questions for the authors.**

1. What is the intended M1 rule for a correct assertion about a character appearing on another character's page, and do the stored labels consistently implement it?
2. Will the human package expose all citations, allow eligible-source search for negative factuality judgments, preserve undecidable answers and derive pair-page support from the participation column?
3. Which seeded sentences have been independently confirmed to convey their assigned gold fact using only the reader's eligible background at each cutoff?
4. What assumptions justify the approximate 2% statement, and how is that population related to the cutoff-mean headline metrics?
5. Which empirical conclusion would change under the upcoming human adjudication or held-out evaluation, and what uncertainty will remain even if those checks agree with the pilot?

**Priority for the next revision.** First fix the human package's evidence and scoring definitions, the M1/cast descriptions, the paired-cutoff calculation and the residual safety/bound wording. Then complete independent annotation and semantic validation of the disclosure fixtures, including a check outside retrieved candidates. Recompute affected values and uncertainty from the adjudicated records before incorporating a held-out study. The current paper is much closer to a credible empirical task paper; the remaining decisive step is evidence that the evaluation protocol measures its declared outcomes reliably.
